# Проверка корректности DataMatrix

DataMatrix состоит из данных с коррекцией ошибок и рамок, по которым сканер
находит отдельные регионы символа. Корректный SVG и правильные размеры ещё
не гарантируют, что сканер сможет восстановить исходные данные.

## Что исправлено

В правой границе каждого региона ECC200 чередование тёмных и светлых модулей
было сдвинуто на одну строку. Первая строка данных должна иметь тёмный правый
модуль, но кодировщик считал чётность вместе с верхней рамкой и ставил светлый.
Пример правильного построения границ есть в
[DataMatrixWriter из ZXing](https://github.com/zxing/zxing/blob/zxing-3.5.3/core/src/main/java/com/google/zxing/datamatrix/DataMatrixWriter.java).

Ошибка находилась в общей логике всех размеров. В частности, существовал
85-байтовый вход, для которого штатный символ 36×36 не декодировался.
Исправление меняет только правые границы регионов: размер, кодирование данных,
padding, ECC и исходные байты остаются прежними. Принудительное увеличение
символа до 40×40 не используется.

API компонента не изменён. После обновления нужно заново сформировать ранее
сохранённые проблемные изображения или документы: установка новой версии
не исправляет уже созданные SVG, PNG и PDF.

## Быстрые PHPUnit-тесты

`DataMatrixEncoderTest` проверяет все четыре границы каждого региона для всех
24 поддерживаемых квадратных размеров — от 10×10 до 144×144. Отдельно проверяет
выбор размера, включая исходную регрессию 36×36.

Набор `DataMatrixCases` общий для PHPUnit и независимых декодеров. Он содержит
61 случай: регрессионный вход, заполнение каждой ёмкости и значения до, на и после
границ 62, 86, 114 и 144 кодовых слов. Данные включают ASCII, пары цифр,
знаки пунктуации, кавычки и байт GS (`0x1D`). Ёмкость считается после кодирования:
две соседние цифры занимают одно кодовое слово, а не два.

Запуск из корня монорепозитория с уже собранным PHP-образом и установленными
dev-зависимостями Barcode:

```bash
docker run --rm \
  -e BARCODE_TEST_SAVE_ARTIFACTS=0 \
  -v "$PWD/packages/Barcode:/app" -w /app \
  phpsoftbox-php-cli php vendor/bin/phpunit
```

Можно также использовать штатный `make php-test` после выбора компонента Barcode.

## Интеграционная проверка декодирования

Обязательна перед выпуском изменений DataMatrix. Она запускается отдельно от
PHPUnit: Python, libdmtx, CairoSVG и Poppler нужны только тестовому контейнеру,
но не пользователям PHP-пакета. Отсутствующие зависимости или пустой/неполный
поток тестовых данных приводят к ошибке, а не к пропуску проверки.

Из корня монорепозитория:

```bash
docker build -t phpsoftbox-barcode-decode:local packages/Barcode/tests/integration

set -o pipefail
docker run --rm \
  -v "$PWD/packages/Barcode:/app:ro" -w /app \
  phpsoftbox-php-cli php tests/integration/datamatrix-cases.php \
  | docker run --rm -i --network none phpsoftbox-barcode-decode:local
```

Команды рассчитаны на Bash. `pipefail` сохраняет ошибку PHP-производителя данных,
даже если тестовый процесс справа завершился успешно. Сборке образа нужен доступ
в сеть для установки тестовых зависимостей; самому декодированию сеть не нужна.

Для каждого случая проверяются:

1. Матрица, нарисованная тестом без PHP-рендерера.
2. PNG, сформированный `DataMatrixGenerator`.
3. SVG того же генератора после растеризации CairoSVG.
4. SVG, преобразованный в отдельную PDF-страницу и растрированный Poppler при 300 DPI.

Каждое изображение должны прочитать **оба независимых движка**: ZXing-C++ 3.1.1
и libdmtx 0.7.7 (через pylibdmtx 0.1.10). Сравниваются именно байты, а не
отображаемый текст: без удаления GS, обрезания пробелов или добавления перевода
строки. Матрицы дополнительно сравниваются модуль в модуль с кодировщиком
libdmtx при явно заданных ASCII-режиме и размере символа. Такое сравнение нельзя
делать между произвольно выбранными режимами кодирования: разные корректные
режимы могут давать разные матрицы для одного текста.

Изображения строятся с четырьмя пикселями на модуль и свободной зоной по четыре
модуля. Проверка PDF подтверждает прохождение тестовой цепочки, но не заменяет
проверку конкретного макета приложения, масштаба печати и физического сканера.
Временные PDF и растры удаляются самим тестом при выходе из каждого случая.
