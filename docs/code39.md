# Code 39

Линейный код переменной длины. Генераторы `Code39SvgGenerator` и `Code39PngGenerator` строят изображение
по тем же правилам, что и остальные генераторы пакета: `BarcodeType::Code39` плюс формат из `BarcodeOptions`.

## Набор символов

Стандартный Code 39 знает 43 символа: `0-9`, `A-Z`, пробел и `- . $ / + %`. Строчные буквы приводятся
к верхнему регистру, остальные символы вызывают исключение с подсказкой перейти на Full ASCII.

```php
new BarcodeOptions(
    format: BarcodeOutputFormat::Svg,
    code39Charset: Code39Charset::FullAscii,
);
```

В режиме Full ASCII любой ASCII-символ кодируется парой из базового набора: `a` → `+A`, табуляция → `$I`,
`@` → `%V`. Важно: сканер должен быть переведён в режим Full ASCII, иначе он прочитает сами пары, то есть
`+A+B` вместо `ab`. Символы вне ASCII (например кириллица) не поддерживаются: для произвольных байтов
используйте DataMatrix или QR.

## Контрольная сумма

`code39Checksum: true` добавляет контрольный символ mod 43. По умолчанию выключена, как и принято для Code 39.

Сканер, который не проверяет контрольную сумму, вернёт её как обычный символ в конце строки: `CODE39` → `CODE39W`.
Поэтому включайте её, только если приёмная сторона действительно проверяет и отбрасывает контрольный символ.

Вместе с Full ASCII контрольную сумму лучше не включать: она считается по значению уже закодированной строки
(`box-7` → `+B+O+X-7`), поэтому контрольным может оказаться символ `+`, `$`, `/` или `%`, а сканер в режиме
Full ASCII попробует прочитать его как начало escape-пары.

## Ширина штрихов и свободная зона

`code39WideRatio` задаёт отношение широкого элемента к узкому: `2` (по умолчанию) или `3`. Стандарт допускает
оба значения; `3` заметно расширяет изображение, но легче читается при печати низкого качества.

Свободная зона — 10 узких модулей с каждой стороны, она входит в `width` результата. Физическая ширина
одного узкого модуля задаётся через `moduleWidth`.

## Подпись под кодом

Под штрихами выводится исходное значение: без символов-разделителей `*` и без контрольного символа.
В SVG подпись экранируется, поэтому данные вроде `a&b` не ломают разметку.

## Проверка независимым декодером

Как и для DataMatrix, корректные размеры и валидный SVG ещё не означают, что код прочитает сканер.
Проверка запускается отдельно от PHPUnit и использует ZXing-C++ в контейнере.

Из корня монорепозитория:

```bash
docker build -t phpsoftbox-barcode-decode:local packages/Barcode/tests/integration

set -o pipefail
docker run --rm \
  -v "$PWD/packages/Barcode:/app:ro" -w /app \
  phpsoftbox-php-cli php tests/integration/code39-cases.php \
  | docker run --rm -i --network none phpsoftbox-barcode-decode:local /tests/code39_decode_test.py
```

Набор случаев общий для PHPUnit и декодера — `tests/Code39Cases.php`: цифры, пунктуация из базового набора,
приведение регистра, контрольная сумма, отношение ширин 3:1, длинное значение и четыре случая Full ASCII.

Для каждого случая проверяются три изображения:

1. PNG генератора;
2. SVG того же генератора после растеризации CairoSVG;
3. SVG, преобразованный в PDF и растрированный Poppler при 300 DPI.

Стандартный набор декодируется как `Code39Std`, Full ASCII — как `Code39Ext`: в расширенном режиме
декодер сам раскрывает escape-пары. Сравнивается ровно тот текст, который ожидает получить приложение.

Контрольная сумма mod 43 проверяется юнит-тестом `Code39Test`: ZXing не валидирует её и возвращает
контрольный символ как часть строки.
